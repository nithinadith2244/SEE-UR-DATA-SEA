Methodology

This page explains exactly how a result is produced, so you can judge how far to trust it.

Where results come from

SEE UR DATA does not hold a breach database. It asks an external breach-data service about the address you enter and shows what that service reports. The default is XposedOrNot's free API, which needs no key and no account; an operator can instead use Have I Been Pwned with a paid key that exists only on the server. The browser never holds a key.

Free-tier limits are real. The free service allows a small number of lookups per hour and per day for each internet address, and describes itself as meant for personal and low-volume use. When a limit is reached you see "Unavailable" with a retry hint, never a guess. If the server has nothing configured at all, you see "Live email breach lookup is not configured yet."

How the service's answers are interpreted

Service answerWhat you see
Breach records in a well-formed answerListed in a documented breach, with details and source.
The service's documented, complete "nothing found" answer (XposedOrNot: an empty result; Have I Been Pwned: a genuine HTTP 404)No match found, with the caveat that this is not a promise of safety.
Rate limit (HTTP 429)Unavailable, with a retry hint.
Rejected credentials (401) or denied access (403), Have I Been Pwned onlyUnavailable, with a distinct message.
Server errors, timeouts, network failures, unreadable or unexpected answersUnavailable. Never shown as "no match".

The three outcomes

OutcomeWhen it is shownWhat it does not mean
Listed in a documented breachThe provider returned a well-formed record for the address and at least one record is marked verified by the provider.It does not mean the data was or is being misused.
No match foundThe provider returned its documented, complete "nothing found" answer.It does not mean the address is safe or was never exposed.
Unavailable or inconclusiveAnything else: no provider, network failure, timeout, rate limit, an unrecognised response, or matches that the source has not verified.It is not a result in either direction.

Safeguards against wrong answers

  • Results can only be created by a small set of validated constructors. Anything else is discarded.
  • Provider responses must match a documented shape exactly. A response that is partly unreadable is rejected as a whole instead of being partially trusted.
  • An HTTP error, a missing field or an unexpected shape never turns into "no match".
  • Text from a provider is displayed as plain text, and links are shown only if they are absolute https addresses.
  • Each result shows its data source and a link to it.

Input handling

The address is trimmed, checked against a conservative email format, and converted to lower case before lookup. Addresses with non-English characters are not supported yet.

Providers considered

The project's docs/PROVIDERS.md records the options examined, their limits and what could and could not be verified. XposedOrNot is the default free service. Have I Been Pwned needs a paid key, so it is used from the server only.
